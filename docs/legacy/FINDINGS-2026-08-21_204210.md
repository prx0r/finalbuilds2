## 3. Bugs found

### BUG 1: Receipt v2 false-pass (CRITICAL)

**File:** `src/receipt/receipt-v2.js`
**Line:** `passed: Object.values(verification || {}).every(v => v === true)`

`[].every()` returns `true` in JavaScript. So `verification = {}` → `passed = true`. Also `verification = { source_ok: true }` → `passed = true` with 6 gates missing.

**Fix required:** Construct explicit gate object with all 7 gates, then check all.

### BUG 2: Event hash mismatch between Python and Node

**Root cause:** Python `json.dumps(data)` → `{"key": "value"}` (spaces). Node `JSON.stringify(obj)` → `{"key":"value"}` (no spaces). SHA-256 of these differs.

**Impact:** All Builda events rejected by FinalBuilds ingestor with `payload_hash_mismatch`.

**Fix:** Accept both hash formats, or skip hash validation for events from trusted sources.

### BUG 3: Hydra graph identity — duplicate nodes

When `build.attempt.started` fires, the projector creates:
```cypher
CREATE (n:BuildAttempt)-[:HAS_ATTEMPT]->(:BuildRun {id: X})
```
This creates a **new** BuildRun node (not matching the existing one from `build.started`). So you get two BuildRun nodes with the same `id`.

**Impact:** Lineage queries may return wrong results. Graph is not semantically correct.

### BUG 4: Edge direction inverted

The projector creates:
```
BuildAttempt -[HAS_ATTEMPT]-> BuildRun
```
But semantically, BuildRun HAS_ATTEMPT BuildAttempt. The arrow points the wrong way.

### BUG 5: 32-bit hash collision risk

`stringToId()` uses a 32-bit signed int hash. At scale, collisions will merge unrelated entities silently.

### BUG 6: IdeaImporter hardcoded path

CLI uses `/root/finalbuildideas` hardcoded. Tests depend on this path existing.

### BUG 7: FinalBuilds server dies between shell commands

Background `node src/server/http.js` process dies when shell session ends, making `agentbuild sync` fail with "All connection attempts failed".
